JEWELLAB DEVELOPMENT MINDSET

We are not simply building webpages. We are building a premium digital learning platform.

Every page must contribute to the student's journey through learning, making, sharing and growing.

Our Core Philosophy

Build with intention. Design with purpose. Keep it simple. Make it premium. Never create complexity without a reason.

RULE #01 — PROTECT THE MASTER HTML

index.html is the main JEWELLAB experience.

External pages must NEVER be copied wholesale into index.html.

The homepage may preview an external feature, but the complete experience belongs to its dedicated page.

Correct 

<a href="pages/community.html">
    Enter Community
</a>

Incorrect 

<!-- DO NOT COPY THE ENTIRE COMMUNITY PLATFORM
     INTO index.html -->

RULE #02 — ONE PAGE, ONE PRIMARY PURPOSE

Every external page must have a clear job.

Page Primary Purpose
courses.html Discover learning paths
course-detail.html Understand and enrol in a course
lesson.html Complete a lesson
project-studio.html Build a jewellery project
community.html Connect with other makers
mentor.html Interact with mentors
showcase.html Explore student work
resources.html Access learning resources
profile.html Manage the student's journey
portfolio.html Present the student's work professionally

RULE #03 — USE SEMANTIC HTML

We use HTML to describe what content means, not merely what it looks like.

Prefer meaningful elements such as:

  • <header>
  • <nav>
  • <main>
  • <section>
  • <article>
  • <aside>
  • <footer>
  • <form>
  • <button>

Avoid turning everything into anonymous div elements simply because they are convenient.

Semantic structure improves maintainability, accessibility and SEO.

RULE #04 — TYPOGRAPHY HAS A JOB

Typography is part of the JEWELLAB identity.

Primary Display

Great Vibes

Interface / Body

Manrope

We do NOT randomly introduce fonts on individual pages unless there is a deliberate design reason.

Headings must remain readable. Decorative typography is an accent, not a replacement for communication.

RULE #05 — COLOUR HAS PSYCHOLOGICAL PURPOSE

  • Lime → energy, growth, creativity
  • Orange → warmth, confidence, action
  • Sky Blue → trust, clarity, learning
  • Pink → expression, creativity, community
  • Black → premium, sophistication, depth

These colours are accents. They do not compete for attention simultaneously.

Every page must maintain the JEWELLAB colour system.

RULE #06 — GRID FOR STRUCTURE

CSS Grid is our primary tool for major two-dimensional page structures.

Flexbox for relationships

Flexbox handles navigation, buttons, alignment, toolbars and smaller component layouts.

We do not use Grid simply because it looks modern. We use it when the content benefits from two-dimensional structure.

RULE #07 — MOBILE IS NOT AN AFTERTHOUGHT

Every external page must work across:

  • Mobile
  • Tablet
  • Laptop
  • Desktop
  • Large desktop displays

We design the information hierarchy first, then adapt the layout.

RULE #08 — INTERACTION MUST SERVE THE USER

Animation exists to communicate, guide or delight.

We do NOT animate everything simply because JavaScript can animate everything.

  • Hover effects should communicate interaction.
  • Transitions should feel intentional.
  • Loading states should reassure the user.
  • Progress animations should communicate progress.
  • Decorative motion should never interfere with learning.

RULE #09 — JAVASCRIPT HAS RESPONSIBILITY

JavaScript controls behaviour.

HTML controls structure.

CSS controls presentation.

We do not use JavaScript to solve a problem that CSS or HTML can solve cleanly.

Global JavaScript 

js/main.js

Page-specific JavaScript 

js/courses.js
js/lesson.js
js/studio.js
js/community.js
js/profile.js

RULE #10 — NO CSS SPAGHETTI

We update existing components before creating duplicate components.

We do NOT create: 

.button-final
.button-final-v2
.button-final-new
.button-rebuild17
.button-rebuild18

Instead, we improve the original component or deliberately create a new reusable component.

RULE #11 — BUILD REUSABLE COMPONENTS

When the same visual pattern appears repeatedly, it becomes a component.

  • Buttons
  • Course cards
  • Lesson cards
  • Progress indicators
  • Profile cards
  • Project cards
  • Community posts
  • Modals
  • Toast notifications

RULE #12 — CONTENT MUST FEEL REAL

We do not fill premium interfaces with meaningless placeholder text everywhere.

Course titles, lesson descriptions, project instructions and community content should feel like they belong to a real academy.

Every piece of content should answer:

Why does the student need this?

RULE #13 — PREMIUM MEANS ACCESSIBLE

A beautiful platform that excludes users is not a premium platform.

  • Logical heading hierarchy
  • Keyboard-friendly controls
  • Visible focus states
  • Meaningful link text
  • Useful alternative text for images
  • Proper form labels
  • Respect for reduced-motion preferences

RULE #14 — DO NOT FAKE THE DATABASE

HTML, CSS and JavaScript create the frontend.

SQL will eventually manage persistent data. 

backend/
└── database.sql

We will eventually design proper relationships between students, courses, lessons, progress, projects, submissions and community activity.

Until then, frontend demo data remains clearly identifiable as demo data.

RULE #15 — NEVER TRUST THE FRONTEND

JavaScript validation improves user experience, but it is not a security boundary.

When we build the backend, authentication, authorization and data validation will happen server-side.

RULE #16 — BUILD EVERY PAGE IN PHASES

  1. Define the purpose.
  2. Define the user.
  3. Define the user's primary task.
  4. Design the wireframe.
  5. Build semantic HTML.
  6. Test content hierarchy.
  7. Apply layout.
  8. Apply typography.
  9. Apply colour.
  10. Add responsive behaviour.
  11. Add JavaScript interaction.
  12. Test accessibility.
  13. Test mobile.
  14. Test tablet.
  15. Test desktop.
  16. Consolidate and document.

RULE #17 — DO NOT SKIP PHASES

We do not jump directly from an idea to a complicated JavaScript interface.

If the layout is wrong, JavaScript will not fix it.

If the information architecture is wrong, animation will not fix it.

If the typography is wrong, adding more colour will not fix it.

Structure first. Design second. Interaction third. Data architecture fourth.

RULE #18 — EVERY PAGE MUST PASS THE TEST

Before we call a page finished:

  • Does the page have one clear purpose?
  • Can a student understand it immediately?
  • Does the hierarchy make sense?
  • Does it feel like JEWELLAB?
  • Does the typography feel premium?
  • Are the colours intentional?
  • Does the layout work on mobile?
  • Does it work on tablet?
  • Does it work on desktop?
  • Is the interaction useful?
  • Is the HTML understandable?
  • Is the CSS maintainable?
  • Is the JavaScript necessary?
  • Can we update the page six months from now without being afraid of the code?

THE JEWELLAB GOLDEN RULE

NEVER ADD COMPLEXITY JUST BECAUSE WE CAN.

Every feature must improve the student's experience.

Every visual element must support the brand.

Every interaction must have a purpose.

Every piece of code must have a home.

Every page must remain maintainable.

And every new feature must fit the larger JEWELLAB ecosystem rather than becoming an isolated experiment.
